Tessera documentation

Vertex consensus for ROS 2

Tessera integrates the Tashi Vertex engine, a hashgraph-based BFT consensus, into ROS 2: every robot submits opaque bytes and every robot receives the same totally-ordered, finalized stream back. Fleets coordinate with no leader, no server, and tolerance of f faulty robots in a fleet of 3f + 1. These tutorials take you from the mental model to a shipping integration.

The tutorial series

Volume 1

Concepts and protocol design

Crate-level internals

Reading order. Study 1 → 2 → 3. In a hurry? Volume 2 stands alone: start there and return to Volume 1 when you design a protocol of your own. Volume 3 is only for processes that cannot be ROS 2 nodes.

The worked example: a consensus-coordinated robot fleet

The repository ships a complete reference application used throughout the tutorials: four simulated robots exploring routes to a goal, coordinating exclusively through consensus. It demonstrates exclusive task claims, blocked-task recovery, winner convergence, lease timeouts for crashed robots, and fleet-wide resets, all built on the same vertex_fleet API you will use, and all covered by tests that run in CI, including fault injection and a randomized mission soak.

  • The vertex_fleet library — the base classes and the minimal ledger example (vertex_fleet/)
